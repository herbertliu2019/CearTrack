# GPU 硬件质检报告 — 测试方案说明

---

## 一、测试工具

### NVIDIA 显卡

| 工具 | 开发方 | 用途 |
|------|--------|------|
| **nvidia-smi** | NVIDIA 官方 | 硬件规格采集、实时热监控 |
| **gpu-burn** | 开源（Ville Timonen / Wili） | VRAM 全载压力测试与错误检测 |
| **glmark2** | 开源（Collabora Ltd.） | OpenGL 渲染性能基准跑分 |

### AMD 显卡

| 工具 | 开发方 | 用途 |
|------|--------|------|
| **rocm-smi** | AMD 官方（ROCm 平台） | 硬件规格采集、实时热监控 |
| **radeontop** | 开源 | GPU 利用率监控 |
| **glmark2** | 开源（Collabora Ltd.） | OpenGL 渲染性能基准跑分 |

> 所有工具均为行业通用标准工具，广泛应用于数据中心运维、显卡出厂测试及第三方评测机构。

## 二、测试设计原理

### 1. 硬件规格全量采集（L1 识别）

测试开始时通过 **nvidia-smi / rocm-smi** 直接从显卡固件读取完整硬件参数，包括：

- 显存大小、类型、位宽
- 驱动版本、GPU BIOS 版本
- PCIe 接口代数与实际带宽
- 核心频率、显存频率
- 板卡厂商、PCI Device ID

这与第三方权威工具 **GPU-Z**（TechPowerUp）的采集字段完全对齐，确保规格数据来源权威、可追溯。

---

### 2. VRAM 全载压力测试（5分钟）

**核心原理：** gpu-burn 将显卡的全部可用显存写满随机数据，随后对每一个内存单元进行反复读取与校验。任何显存颗粒存在物理损伤（虚焊、老化、电容失效），都会导致读回数据与写入数据不一致，系统记录为 **错误计数**。

**为什么是 5 分钟：**
- 显卡从冷启动到温度稳定需要约 3 分钟
- 许多显存缺陷只在高温下才会暴露（热膨胀导致虚焊接触变差）
- 5 分钟确保显卡充分热透，捕获热稳定性相关的间歇性故障

**行业对比：** 二手显卡市场最常见的欺诈方式是"刷 BIOS 掩盖错误"，gpu-burn 通过底层内存校验绕过驱动层，直接检测物理 VRAM 健康状态。

---

### 3. 全程热监控（1秒采样）

**核心原理：** 在整个压力测试期间，系统每秒采集一次：
- GPU 核心温度
- GPU 利用率
- 实时功耗
- 核心/显存频率

**为什么重要：**
散热系统失效是显卡最常见的隐性故障。一张在室温下工作正常的显卡，在满载 3 分钟后可能出现温度失控（>90°C）或频率降速（Thermal Throttling）。这类问题在简单开机验机时完全不可见，必须通过持续负载才能暴露。

**判定阈值：**
- NVIDIA：>85°C 警告，>95°C 判定失败
- AMD：>80°C 警告，>90°C 判定失败

---

### 4. OpenGL 渲染跑分（glmark2）

**核心原理：** 运行标准化 OpenGL 渲染场景，测量：
- **几何处理能力**（build 场景：VBO 顶点缓冲区吞吐量）
- **纹理采样能力**（texture 场景：纹理过滤性能）
- **着色器计算能力**（shading 场景：逐像素光照计算）

输出统一的 **glmark2 Score**，可与同型号显卡基准分对比，低于基准 80% 触发警告。

**意义：** 验证显卡的渲染管线完整可用，排除驱动异常、显存带宽不足、核心单元损坏等问题。

---

### 5. 系统日志错误扫描（dmesg）

**核心原理：** 扫描 Linux 内核日志，过滤 GPU 相关的严重错误信息，包括：
- NVIDIA Xid 错误（驱动级严重故障代码）
- amdgpu / nvrm 驱动报告的 hang / reset 事件
- DRM 子系统错误

**为什么重要：** 部分显卡故障不会导致程序崩溃，但会在内核日志留下错误记录。这是操作系统层面对硬件健康状态的独立判断，与应用层测试互相印证。

---

### 6. PCIe 接口完整性检测

**核心原理：** 对比显卡报告的"当前 PCIe 带宽"与"设计最大带宽"。

**实际意义：** eBay / 二手市场最常见的隐性问题之一是显卡金手指氧化或插槽接触不良，导致 PCIe 链路从 x16 降速至 x4 甚至 x1，影响数据传输性能。本测试自动检测并报告此问题。

---

## 三、综合判定标准

```
FAIL（不通过）— 任一满足：
  ✗ VRAM 错误计数 > 0
  ✗ 内核日志存在 GPU 严重错误
  ✗ 满载温度超过安全阈值

WARN（注意）— 无 FAIL 时：
  ⚠ 温度偏高（接近阈值）
  ⚠ PCIe 带宽低于设计值的一半
  ⚠ 渲染跑分低于同型号基准 80%

PASS（通过）— 以上均无
```

---

## 四、测试报告可信度

每次测试自动生成结构化 JSON 报告，包含：
- 完整硬件规格（可与官方数据手册核对）
- 原始热监控日志（每秒记录，可回溯）
- 错误计数与内核日志原文
- 测试时间戳与设备序列号

报告上传至中控服务器存档，**不可事后篡改**，作为质检合格证明的原始依据。

---

*本测试方案参考数据中心 GPU 运维标准，结合回收翻新场景的实际需求设计，覆盖消费级与专业级显卡（NVIDIA GeForce / Quadro，AMD Radeon / Pro）。*
